# 苹果与谷歌商店应用名称检查（App Store & Google Play Name Check）

输入一个拟用的 App 名称和目标市场，输出 01–05 项命名审计报告：
字符长度、商店实时同名检索、违禁词、Emoji 与符号、商标预检。

## 五项分工

| 项 | 内容 | 谁判定 |
| --- | --- | --- |
| 01 | 字符长度（30 上限，按字素簇计数） | 脚本 |
| 02 | 同名与排他性（各目标市场实时检索 + 占位名） | 脚本 |
| 03 | 价格、促销、排名、官方暗示、误导性词 | 脚本 |
| 04 | Emoji 与非标符号 | 脚本 |
| 05 | 商标与品牌冲突 | **调用方模型** |

05 项由脚本准备素材（`brandReview`），由模型用自身品牌知识完成——脚本不内置品牌词表。

## 联网与数据

- 检索同名时会实时请求两家商店的公开接口：Apple 的 `itunes.apple.com`（官方搜索接口）
  与 Google Play 的 `play.google.com`（商店页面）。
- 被检名称会以明文出现在这些请求里 —— 这是商店检索的必要条件；除此之外不发送任何数据，
  不在本地写任何文件，也不回传到其他服务器。
- 传 `--offline` 可完全不联网，只跑本地规则，此时 02 项显示「离线未检索」。

## 已知限制

- **Google Play 结果靠页面解析**，依赖 Google 的混淆 CSS 类名，可能随改版失效。
  解析不出结果时会在 stderr 给出告警，此时该平台的检索结果不可信，需人工到商店页面核对。
- **未收录语言映射的市场回退英文检索**，该市场本地语言下的应用名可能检索不到。
- **跨语言名称仍不匹配**：简繁已归一化，但中文名与日文/英文写法之间不会互通。
- **03 项有「待复核」档**：`best` / `top` / `第一` / `最好` 这类词同时是常见词，
  单凭命中无法区分是宣传还是名字里恰好有这个字，脚本不阻断，只列出供按语境判断。
- **Google Play 检索结果的开发者列未校验**：页面解析可能把相邻卡片的开发者串位，
  引用归属请以「应用名 + 商店链接」为准；Apple 侧走官方接口，不受影响。
- **Google Play 结果不含类目字段**：当前解析只取应用名与开发者，未取到真实类目就留空，
  不用占位值顶替。
- **05 项完全由调用方模型完成**：脚本不内置品牌词表，只提供待核查的候选词、尼斯类别与官方渠道。
  脚本侧的 05 项状态是「未判定」，结论必须由模型补上。
